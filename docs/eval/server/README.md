| 파일 | 내용 |
|---|---|
| `rag_eval_server_console.txt` | 콘솔 출력 (문항별 O/. 표와 방식별 Recall@3, 문서별 점수) |
| `rag_eval_server.json` | `--out`으로 저장한 JSON (방식별 결과) |

## 측정 조건
| 항목 | 값 |
|---|---|
| 측정 시각 | 2026-11-19 14:55 KST경 (서버 시각 05:55Z) |
| 실행 방법 | 서버에서 파드 `rag-eval-final`을 일회성으로 실행 (`kubectl run`, 이미지 `ghcr.io/hanjyoon01/edr-ai-triage-kb:0.1.0`, `app-config`·`app-secrets` 적용) |
| 평가 코드 | 위 이미지에 들어 있는 `soc.eval.rag_eval`. 이미지는 `b02f37e`(PR #31 머지) 시점의 작업 트리로 로컬에서 빌드해 푸시했고, 최신 `main`과 다를 수 있다 |
| 설정 | `FAKE_LLM=false`, `KB_TOOLS=real`, `EMBED_MODEL=text-embedding-3-small`, `CHUNK_MAX_CHARACTERS=700`, `PARSE_STRATEGY=fast` |

| 적재 | `kb-ingest` Job, 완료 `2026-11-19T03:21:27Z`, 700자 설정으로 적재 |

## 이 파일의 출처에 대한 정직한 설명
서버에서 처음 0.905를 측정했을 때는 요약 줄만 확인했고 콘솔 전체와 JSON은 저장하지 않았다. 이 폴더의 파일은 **같은 서버 상태(인덱스, 설정, 이미지)에서 다시 실행한 결과**이며, 처음 측정과 세 방식의 값이 같았다(키워드 0.905, 벡터 0.857, 합친 검색 0.905).

## 로컬 결과와 다른 점 (환경 차이)
로컬 인덱스는 청크 19개, 최대 1052자, 평균 730자로 적재 값을 확인하지 못했고, 서버 인덱스는 700자 한도에 맞는 분포다. 서버 결과가 기준점(합친 검색 0.857)보다 높지만, 임베딩(가짜가 아닌 실제 임베딩), 청킹, 적재 환경이 함께 달라서 청킹만의 효과라고 단정할 수 없다.
