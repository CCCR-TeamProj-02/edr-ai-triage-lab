- 실제 로그 구조에 맞춰 `index_template.py` 매핑 작성. `host`, `type`, `process.name`은 `keyword`(정확한 값 검색·필터), `ts`/`pid`·`ppid`/`dst_ip`는 `date`/`long`/`ip`, `process.cmdline`·`script_text`는 `text`+`keyword`(단어 검색과 정확한 값 검색 모두).
- 3,161건 적재 후 전체 3,161건 확인. `evt-00003004` 검색으로 내용 일치 확인.

- 부모 기록 누락과 검색 오류를 구분해야 한다.
- 트리 도구 결과 칸: `host`, `pid`, `process`, `ancestors`, `children`, 각 기록에 `event_id` (`CONTRACT.md` 기준).

## 📘 문서 담당이 설명한 것
- `search_playbook(query, k)`는 한국어 질문을 받아 `[{source, page, category, text, score}]`를 최대 `k`개 돌려준다. `source`는 파일 이름이라 권고에 출처를 붙이는 데 쓴다.
- 만드는 순서: PDF → 요소(Title, Table, Header 등 종류가 붙은 글 조각) → 청크(검색 단위, 기본 800자) → 저장. 파싱은 `fast`로 했다.
- 머리말·꼬리말은 "Header/Footer로 분류됨 + 여러 쪽에 반복 + 10자 이상"일 때만 뺀다. 카테고리만 보면 본문 소제목까지 지우기 때문이다.
- `score`는 합친 검색(RRF)이면 최대 약 0.03이라 크기로 좋고 나쁨을 판단하지 않는다.
- 아직 안 된 것: 표를 행 단위로 살리기(01, 09), 스캔본(06). 검색은 OpenSearch가 뜬 뒤 Recall@3로 잰다.
